## Scope and how to interpret dates

The [Android App Security Improvement Program](https://developer.android.com/privacy-and-security/googleplay-asi) is a security service for Google Play developers. Its overview says apps are scanned before acceptance and continuously rescanned. When a potential issue is found, Google sends an email and Play Console alert linking to a support article. Notices typically include a remediation timeline; some issues can block further app updates. After uploading a fixed version with an incremented version number, developers can check the Console again after a few hours to see whether the alert has cleared.

**Do not treat the campaign table's Started dates as current deadlines.** The listed campaigns began between 2014 and 2022. Those are historical start dates. The affected apps, remediation deadline, publishing impact, and alert status for a particular developer are shown in that app's Play Console notice. Historical SDK version floors are not current recommendations for the latest version.

The official directory separates warning campaigns with a remediation deadline from warning-only campaigns with no remediation deadline. For example, the Implicit PendingIntent article says remediation is recommended but not mandatory and will not affect publication status. Not every security notice is a removal countdown.

## Shared remediation and release checks

1. Use the Play Console alert to identify affected apps, code locations, tracks, deadlines, and the applicable remediation page. Do not decide from the campaign label alone.
2. Inventory app code, dynamically loaded code, packed/obfuscated output, ad/analytics SDKs, and transitive dependencies. Removing a secret from current source is not enough if an older published version still exposes it; rotate or revoke leaked credentials too.
3. Increment the version after fixing the issue and submit compliant APKs or App Bundles to every affected track. Wait for review and confirm the original alert state in Console; continue from the email/Console notice if review fails.
4. Keep technical remediation separate from policy analysis. Review User Data, Data safety, Malware/Dangerous Products, and DDA duties independently against the app's actual behavior.
