## Distinguish the two audience sources

Custom store listings can show different copy and assets by country or region, pre-registration status, search keyword, ad traffic, or user segment; up to 50 custom listings can be created. Each listing must accurately describe the app and follow Metadata and other applicable policies. Custom listings are not automatically translated, so developers need to provide translations for target languages. Contact details, the privacy policy, and app category are shared across listings. See [Store Listing and Asset Best Practices](../store-listing-best-practices/store-listing-best-practices.en-US.md).

Play Console custom audiences have two data sources:

1. **CSV email lists:** Help requires at least 5,000 addresses in the original file. Matching usually takes about 24 hours. An audience expires after 90 days and must be refreshed with a new file containing more than 5,000 addresses. If the match count falls below the threshold or the audience expires, events using it may pause. This is a product eligibility condition; it does not give the developer a legal basis to collect, upload, or market to those email addresses.
2. **Google Play Grouping API:** Developers use tags to describe user attributes or behavior, then define audience rules in Console and target Play Store content. The documentation currently describes tag-based targeting for Promotional Content; access is limited to selected eligible partners.

## Grouping API privacy and security constraints

- On first use, Play displays a notice to the user about the data exchange. Google provides opt-out controls, which the documentation links to [My Activity](https://myactivity.google.com/myactivity). This does not mean an app can skip its own applicable disclosure, consent, or Data safety assessment.
- When an app creates a persona from its own user/profile identity, the persona must be an opaque encrypted or hashed string without sensitive or personally identifying information. User tags must also exclude sensitive or personally identifiable data such as names, passport numbers, health data, or ethnicity.
- For apps, the server must verify a generated token before it can be used to write tags. Verification is a mandatory security step. The SDK call requires the app to be in the foreground and surfaces a first-use notice. Games and ordinary apps use different token-generation flows.
- The integration guide states a 30-day token TTL and a 90-day tag TTL. It also specifies persona/tag size and tag-key limits. These values may change; check the current integration guide.
- Both email lists and Grouping API associate audience/user-tag data with Play Store targeting. Review the actual data flow against [User Data](../user-data/user-data.en-US.md) and the [Data safety form](../data-safety/data-safety.en-US.md): if the app or an included SDK collects/transmits email, user IDs, or tags, check transparency, purpose limitation, prominent disclosure/consent where applicable, and consistency with the privacy policy and Data safety declaration. Data safety lists email address as Personal info and includes advertising/marketing and personalization as purposes. Whether a developer's separate Console upload of an external CSV belongs in a specific app form cannot be inferred from this feature Help article alone; determine that from the app's actual processing and the form's definitions.

## Relationship to Promotional Content and eligibility

Promotional Content can surface offers, limited-time events, new content, and major updates on a store listing and other Play surfaces. Custom audiences can target eligible events to a specific group. See [promotional content](../promotional-content-and-best-practices/promotional-content-and-best-practices.en-US.md). This is separate from ordinary store listing assets shown without audience targeting.

The [Premium growth tools eligibility page](https://google.play/business/guides/premium-growth-tools/) lists requirements such as developer-account good standing, app category, active installs, MAU, and spend, and describes temporary access for some new games. Metrics and supported categories can change. The existence of a custom-audience Help page does not mean the feature is enabled for a particular Console account. Account permissions and audience status require authorized access.
