# Rejection and Appeals / 拒审与申诉

## First response

1. Preserve the exact notice, timestamp, app version, platform, storefront, track, and reviewer message.
2. Separate the stated rule from assumptions about the cause.
3. Reproduce the issue using the same account, region, device, build and configuration.
4. Map the issue to the current official source.
5. Decide whether to fix, clarify, provide evidence, or appeal.
6. Record the final response and the next review date.

## Evidence pack

- Submitted build and commit identifier
- Store listing and screenshots used for the submission
- Review notes and demo-account steps
- Device, OS, locale, region and account matrix
- Privacy, SDK, payment and permission evidence
- Backend/configuration snapshot where remote behavior matters
- License, regulatory or partner documentation where applicable
- Exact policy source and version date

## Editorial rule

A community report can reveal a useful test case, but it cannot override the current Apple or Google rule. An appeal document must state what is verified, what changed, and what remains uncertain.

## Platform entry points

- Apple: [App Review](https://developer.apple.com/app-store/review/)
- Google Play: [Policy Center](https://play.google.com/about/developer-content-policy/)
