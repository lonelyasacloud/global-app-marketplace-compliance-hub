# Apple Review Readiness

## Before review

- The submitted build matches the listing metadata, screenshots, previews, and released experience.
- App Review Information explains the purpose, core flows, special hardware, regional differences, and reproduction steps.
- When sign-in is required, provide working demo credentials, roles, test data, MFA instructions, and reset steps.
- For paid features or subscriptions, provide reproducible navigation, test products, and review notes.
- Privacy, support, account deletion, and required backend services remain reachable during review.
- No hidden, dormant, post-review-only, or undocumented functionality exists; remote configuration must not change the key reviewed experience.
- Keep evidence ready for age ratings, Kids, UGC, health, finance, VPN, gambling, crypto, and other regulated capabilities.

## Metadata and assets

The name, description, keywords, screenshots, previews, in-app events, and creative assets should accurately reflect the current build, intended audience, and real functionality. Prices, discounts, comparisons, and performance claims must be verifiable and compliant.

## Evidence

Retain the final build identifier, device matrix, account instructions, review notes, configuration snapshot, privacy and SDK inventory, IAP tests, regional differences, and submission status.
